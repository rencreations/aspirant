# Project rules

**New session? Read `docs/HANDOFF.md` first** (what the project is, how the owner works, the machine's quirks, the systems, the known caveats), then `docs/HISTORY.md` for why things are as they are. Probes for checking a running site are in `scripts/qa/probes/`.

The Aspirants: a static, immersive Next.js site for the Aspirant story series. Read `README.md` and `docs/design/` first. These rules apply to every change.

## Loading: everything goes in the progress bar

The first loading screen and every page transition report real work. Keep it that way.

- Anything a page needs on first paint is declared in `apps/web/src/lib/route-preloads.ts` as a `PreloadItem` (an image, a data file, a lazy code chunk, fonts). The loading bar, its label and the preloading all come from that list.
- When you add an asset, a lazy chunk or a data fetch that matters at first paint, add it to the list for that route. If it is not in the list, it is not in the bar and the page will pop in late.
- Pre-load for speed: warm the cache before the page opens. Items run in parallel, share a cache, and wait as long as the connection needs. An item that the page does not show until the visitor asks (the other pages' clips, the shorts, the trailer, the voice lines of Selena's and Obsidia's pages) is `deferred`: the bar does not wait for it, it keeps downloading in the background once the page is open, in order of `priority` and behind anything urgent, and the button that needs it shows its loading state until it has arrived. Only the first screen is waited for: the welcome, the idle loop, the buttons, the music and the page the visitor landed on.
- A component with a slow first paint (a WebGL scene) calls `expectReady(id)` from `lib/page-ready.ts` and marks itself ready once it shows something, so the curtain waits for it.
- Big media (the Selena videos, skill clips, trailer, music) is loaded whole into memory through `lib/media-store.ts` by a `PreloadItem` that reports the bytes received, so the bar is real, and it is saved in the browser (Cache Storage) so the next visit does not download it again. Small files read as bytes (data, voice lines) use `cachedFetch`. Replacing a file under the same address means bumping the cache name in `media-store.ts`. Her page and its three pages (`/character/selena/{about,skills,gallery}/`) share one list. Obsidia's page and her three pages (`/character/obsidia/{about,skills,gallery}/`) do the same.
- Never fake progress. Never add a timer that pretends to load.
- **One version only. A slow connection waits behind the loading screen** (owner decision, 1 Nov 2026). There is no lite or cut version of the site, and no time after which a page opens with part of its files. The first loading screen and every page change wait for the whole waited list, however long it takes. The screen says the connection is slow after 15 seconds (`SLOW_AFTER_MS` in `components/loader-gate.tsx`) and then shows the real percentage and bytes received. There is no "Enter now" button, no cap on the first visit, on an item or on a page change, and no per-item `timeoutMs`. Never add one.
- A download that stalls (no byte for 20 seconds, `STALL_MS` in `lib/media-store.ts`), drops, fails with a server error or ends short of the length the server gave is started again after a short wait (1 s growing to 10 s, `lib/retry.ts`), for as long as it takes. Pictures, data, voice lines and code chunks do the same through `lib/preload.ts`. The only item that is skipped (and logged) is one the server says is gone (HTTP 404 or 410) or a picture that arrives whole and cannot be decoded five times: nothing can fix those, and one missing file must not hold every visitor for ever.
- Offline, the loading screen keeps waiting, says so ("Offline. Waiting for the connection."), and goes on by itself when the connection returns. A page change that is already running waits the same way. A click on a page that was never opened, while offline, still shows the calm notice (`components/offline-notice.tsx`) and does not start. A stale tab that asks for a file of an old deploy reloads once (`lib/chunk-guard.ts`), never in a loop and never while offline.
- Before the scripts have started, the cover painted by the boot script in `app/layout.tsx` (`.gate-cover`, with its own notes) stays up: the plain server text of the page is never shown to a visitor, whose connection is slow or not. No timer lets it go. Its only exit is the "Reload the page" link it shows after 90 seconds, for a visitor whose scripts have really failed. `/character` has the same rule for its black cover (`roster-cover.tsx`); only a visitor without JavaScript has it hidden (a noscript rule).
- Never let a progress callback move the curtain after the page has started to open: the curtain's `setBoot` must only overwrite its own bar.
- Waited means the first screen and everything that animates or shows on the sections near the top of the page (small pictures, the autoplaying muted clips of the first sections, the music). Only what the visitor must ask for stays `deferred`: the long films, full size art, the room, the other pages' clips and the voice lines. A page whose deferred item is not there yet when the visitor asks shows the button in its loading state, never a different page.
- A document load of `/` (a visit from outside or a reload) runs the home's own opening instead of the curtain: a loading screen with the 3D drone and the real bar, then one press ("Touch anywhere to continue", asked for only when the whole waited list has arrived, so it is not an "Enter now"), then the intro. See "The home page". A move inside the site to `/` uses the curtain.
- A page that is not ready 500 ms after a navigation shows the loading state of the logo transition. Do not remove that.

## One version

There is exactly one version of the site, the full one. It is the same on every device and every connection. There are no performance levels, no lite or balanced mode, no governor that steps effects down, no `?quality` switch, no `<html data-perf>`, and no choice of a smaller video because of the device, the memory, data saving or the speed of the link. The site also ignores the operating system's `prefers-reduced-motion` and has no "Reduce motion" toggle and no `<html data-motion>`. This is the owner's decision (1 Nov 2026). The trade-off is that a visitor who asks their system for less motion still gets the motion. A slow connection or a weak device waits behind the loading screen until everything is loaded, and is never given less. Do not add a reduced, lite or fallback variant of any effect, video or scene (the plain no-WebGL fallback of a scene, a failed download and a browser that cannot play a file are not versions, they are failures to be handled).

## Performance

The site must not lag on an ordinary laptop. Read `docs/design/performance.md`. The rules that matter every day:

- Never write a CSS custom property or an inline style on `<html>` or `<body>` per frame (it restyles the whole page), and never give an element an attribute that a script then selects by. A test guards the cursor.
- Animate `transform` and `opacity` only. No `width`, `left`, `top` or `margin` in an animation. No `filter`, `backdrop-filter` or `mix-blend-mode` over the live picture or on an element with animated children. No per-frame SVG attribute writes.
- A transition between two sections of a long page (Vexana's page) is made by the layout, not by an overlay that appears over the next section for no reason: the section holds its last screen, then a scene plays by itself and the page jumps to the next section while the screen is covered (or the next section simply rises over it, or a heart of colour closes on it as the visitor scrolls). There is no scroll indicator of any kind in a transition. The sections 05 to 09 (the stream, the interactive drama, the 3D process, the gallery and the fanart) have no transitions at all: they follow each other as one plain, smooth scroll, each arriving with its own reveals, and nothing covers the page. The join in front of the stream (the comic) and the ones after the fanart keep their scenes. A lower join works both ways: the next section has no threshold when you arrive by scrolling down, and has one when you scroll up out of it (the same scene plays back). A stop inside a transition snaps one second after the last input (half or more goes on, less goes back), so nobody is left standing in one. While a timed scene plays the scroll is locked (`seams/scroll-lock.ts`) and it is given back only when what arrived is in view and can be used, so nobody scrolls past a heading by accident. It waits, with a real progress and never a timer, for what the next section needs. See `seams/` and `docs/design/design-system.md`.
- Something that follows a video runs on the compositor (a Web Animation), not in a frame loop. Long text and long lists use `content-visibility: auto` and are built in small slices.
- The long character pages (Vexana's and Guinevere's) hide the browser's scrollbar (`BareScrollbar`, `html[data-bare-scroll]` in `styles/base.css`), because a scrollbar that vanishes while the scroll is locked and returns after it moves the page sideways. The one progress mark is the hairline along the top of the screen (`components/hud/hud-frame.tsx`). Do not bring a scrollbar back on those pages.
- Judge speed on the production build, not `pnpm dev` (it is 2 to 3 times slower), with `scripts/perf/weak.mjs`.
- Effects are never gated on the device. If an effect costs too much, make it cheaper for everyone (transform and opacity, the compositor, `content-visibility`), do not turn it off on some devices.

## Logo

The logo is a vector (`components/logo/`, traced from the bitmap by `scripts/logo/build.py`). Use `AspirantLogo` wherever the logo appears. The letters are windows: the plate never covers them. The page transition (`components/curtain/`, `components/transition/`) zooms through those windows.

## Navbar and menu

`useNavLock` also has `hideLogo` and `hideControls` for the home's opening (the bar clears them when the path changes to any other page).

The bar is sticky and always visible. Pages open from the full-screen menu (`components/nav/`), not from links in the bar. Each page has a pair of aspirants shown as art only, never with names, big on the empty left and right of the menu, where they stay (they do not follow the titles) and swap when another page is hovered. The menu art is built by `scripts/menu/build.py` so every figure has the same size, the eyes of both sit on one horizontal line, and no cut of the source shows (it fades out). If you add or change a portrait, rebuild with that script. The art is warmed after the site opens and is not part of the loading bar.

## Video

Use the custom player in `components/video-player/` (`VideoCard`) for new videos, not a bare `<video controls>`. Videos never start by themselves, with nine exceptions. One: the story page (`/story`) plays its hero film muted and in a loop while it is on screen and not covered by the page that rises over it (it is paused otherwise, and held behind its still when it cannot play). Two: the chapter pages of the story (`/story/prologue`, `/story/chapter-NN`) play their title-card loop and the muted clips set in the text while they are on screen (a clip that kept its sound has a button; nothing plays with sound by itself). Three: Vexana's page plays some muted pictures by itself while they are on screen (the signature short, the Reel preview, the skin video of the Registry, the Craft clips, the cover film `final2`, the 3D process clip and the Guinevere dance), they pause when they leave the screen, and none has sound; the livestream also starts muted by itself while on screen and gets its sound when the visitor presses the sound button, and the game starts only when the visitor presses a button, and then plays with sound. Four: the Films room of the collection (`/collection/video/films`) plays the film on screen by itself, with sound only when the site sound is on and the visitor has pressed something on the site (otherwise muted, with the Sound button showing a hint), and pauses it when it leaves the screen; it uses its own player (a bare `<video>` per film held in `features/library/video/films/film-pool.ts`), not `VideoCard`. Five: the Animation room (`/collection/animation`) plays the welcome of the character in front when she arrives and then her idle loop, muted, while she is on screen (the stage engine, no sound); its full screen view plays the character's clips when the visitor presses an option. Six: the Design room (`/collection/design`) plays the design team's own film, muted and in a loop, behind its title while it is on screen, not covered by the page that rises over it and not covered by an open post (`features/library/design/stage.tsx`, made by `scripts/library/design/hero.py`); it is held behind its still when it cannot play. Seven: the About page (`/about`) plays its loop of how the series started (`public/video/about/`, cut from the studio's own film by `scripts/about/start.py`), muted, in the small preview of its first screen and in the big window the preview grows into, while it is on screen, the tab is visible and the player is closed; its play control opens the whole film with sound in the site's player (`PlayerOverlay`); and every video the page shows further down (the window of each phase's videos, the music video, the voiced comic, the plates of TheMLabel's close) plays a muted preview of itself while it is on screen, one at a time in its part, with its source given only when the part is near the screen and taken away when it is far (owner's request, 16 Nov 2026). Eight: the Voicelines room (`/collection/voicelines`) plays its film, muted and in a loop, behind its title while it is on screen and not covered by the page that rises over it (`features/library/voicelines/stage.tsx`, made by `scripts/library/voicelines/hero.py`); it is held behind its still when it cannot play. Nine: the home page (`/`) plays muted pictures and short clips by itself while they are on screen (the angled rows' film, the strip's trailer loop, the ten preview clips, the character loops of the list) and pauses them when they leave the screen; none has sound, and sound comes only after a press (see "The home page"). On the About page sound comes only from the site's player. Her page is built by `scripts/vexana/build.py` (see `docs/superpowers/specs/2026-10-24-vexana-page-design.md`). Guinevere's page (`features/character/guinevere/`) follows it: her files are made by `scripts/guinevere/build.py` (and `glow.py` for the second picture of her hero), the joins, the comic, the interactive drama and the 3D process are Vexana's own (`features/character/vexana/`), and the film, the second film and the heart dance are Vexana's files. Selena's page is built from recordings cut by `scripts/selena/build.py`, and Obsidia's by `scripts/obsidia/build.py` (both run on the engine in `features/character/stage/`): do not re-cut by hand, change the constants there and rebuild. The page picks the size that matches the visitor's display (width, height and pixel ratio, nothing else: the device and the connection never lower it) and loads that size (Selena's and Obsidia's pages wait before opening only for the welcome and the idle loop, and keep loading the rest in the background). While a page or a short waits for its frame the waiting video runs faster (the time skip in the stage engine). The videos have no sound (muted): sound is the music and the voice lines. Keep a video that plays beside the stage at 60 fps, since a 30 fps one makes the page pace at half rate.

Ruby's and Angela's pages are one pair on one view (`features/character/duo/`, routes `/character/ruby/` and `/character/angela/`): Ruby's is the night shift (a blueprint of her art shows through the pointer), Angela's is the first sunrise (a warmth map of hers). Their films are the site's own files in `public/video/ruby-angela/` (not encoded again, they play only when the visitor presses play); the second hero picture and the strip of stills are made by `scripts/ruby-angela/build.py` (the anaconda Python, Pillow and numpy).

Lesley's and Chang'e's pages are two ends of one channel (`features/character/lesley-change/`, routes `/character/lesley/` and `/character/change/`): Lesley's first screen is a scope that magnifies her splash art and fires a thread of light (hold to steady, let go to fire), Chang'e's is a bench with guides, pins that measure each other and markers on her gear. Both show their own splash art full bleed, share the order of the sections and a pill that leads to the other end, and use the site's own files in `public/video/lesley-change/` (they play only when the visitor presses play). Nothing is encoded for them: the sources hold no music, no cut-outs and no fan art for this pair.

## The story (`/story`)

`/story` is the story: a landing page (`features/story/landing/`) and the book, read one chapter to a page (`/story/prologue`, `/story/chapter-01` to `/story/chapter-87`, and `/story/the-end`; `features/story/reader/`). `/about` was the world explainer until 15 Nov 2026 and is now the page of the series (see "The About page" below). The owner swapped the two on 1 Nov 2026 and `/experience` only redirects. On 3 Nov 2026 the owner replaced the old novel with the new one (`story/main.md` of the source folder) and asked for a heavily visual read: images, comic panels, film clips, voice lines and music in the right place of every scene. That reversed the plain-text rule of 1 Nov. Rules:

- The text, the visual scripts and the media all come from `scripts/story/` (`build.py`; see its README and `docs/superpowers/specs/2026-11-03-story-visual-reader-design.md`). Never edit `public/data/story/*`, `public/img/story/*` or `public/video/story/*` by hand: change the novel or a `scripts/story/visuals/cNN.json` and run `build.py`.
- A chapter page opens with a full-screen title card, then runs as one column of text on one plain colour (white, or the site's black; the visitor picks it in the reading settings, one theme for the whole story, no chapter changes it). Set between the paragraphs: wide stills, comic panels, muted clips, place shots and character cards. Voice players sit under the recorded lines and a music score runs under the chapter (only when site sound is on). Everything that moves is transform or opacity. One chapter is one page, never an infinite scroll, and the text is in the page's HTML at build time.
- Pictures illustrate the text and never add to it. Only official art, official comics and official films (the validator in `scripts/story/visuals.py` rejects fan art, cosplay, edits, gameplay, in-game animation and the live-action parody). A picture never shows a character or a reveal before the book does.
- The book has six acts, one pair each (`ACTS` in `scripts/story/build.py`): I The Record 0 to 8, II The Free Land 9 to 16, III The First Aspirants 17 to 30, IV The Emblem of Hope 31 to 47, V Behind the Sky 48 to 67, VI The Singularity Crisis 68 to 87 (restructure of 9 to 11 Nov 2026, `scripts/story/RESTRUCTURE-TASK.md`). Chapters 0 to 17 were curated by hand over six owner rounds: do not change their pictures without the owner. Chapters 18 to 87 must keep 45 words of text between pictures. The reader's save is version 3.
- A link to a chapter of the book is built only by `chapterHref` (`features/story/chapter-href.ts`). `storyChapterHref` is for the character pages, which still carry text from the older story: it maps an old chapter id to the nearest chapter of the book (`legacy-map.json`). Those pages need their own pass.
- On a chapter page the top bar is **locked** to the reading theme and never follows the picture behind it (`lib/nav-lock.ts`, set by `ReaderRoot`): no background at all over the title card, a plain solid bar from the text on, no fade. A picture of the text opens in the plain **viewer** (`reader/viewer.tsx`: press to zoom in on the spot, press again to zoom out, drag to move, press the empty space or Esc to close). The panels of a comic row share one height. No clip may show a burned-in subtitle (crop it out in its visual script). Film lines are `voice` inserts cut from the film's sound.
- The reader saves the place (`aspirants:reader`, versioned by the book, and `aspirants:prefs` `lastChapter`): keep both keys. `furthest` in `aspirants:reader` is the highest chapter reached and opens sealed pictures.
- The landing: Continue is the call when a place is saved, Start reading is the call for a fresh visitor, and the row never shows the wrong one first. The hero film is `scripts/story/hero.py`'s output and is waited for in the `/story` list. The join under the hero is Vexana's pair to interlude join (`features/story/landing/rise.tsx`): keep it a cover-up by the layout, with a snap after one second and no scroll cue inside it.
- The landing says nothing that gives the story away: the description and the cards use no `laterInStory` text, and a chapter picture that would reveal something is sealed (`spoiler` in its visual script) until the visitor has reached that chapter.
- **Between two chapters of the book the logo curtain does not run: the chapter morph does** (`features/story/morph/`, spec `docs/superpowers/specs/2026-11-04-chapter-morph-design.md`). The card at the foot of a chapter (`Door.tsx`) is a small live copy of the next title card (the same picture with the same crop, from the entry's `focus`, its loop playing while it is on screen); a press opens it into that title card. A pull past the end of the page (`ChapterPull.tsx`, `pull.ts`) does the same, a pull past the top closes the title card back into the card of the chapter before, and "Before:" (`BeforeLink.tsx`) unrolls the chapter before from the top. The layer is `MorphLayer` in the root layout (`morph-layer.tsx`, `overlay.tsx`, `choreo.ts`). Rules: transform and opacity only, Web Animations with two keyframes and one easing (the window is two nested clips that only translate, `morph-math.ts`, so nothing is stretched); the next chapter's list is warmed (`warm.ts`) and a card pressed before it has arrived shows the real progress; the morph claims the transition router, so the curtain and a morph never overlap; Lenis is not paused (that hides the scrollbar and moves the page sideways), a capture guard holds the scroll instead; any failure removes the layer and opens the page with the curtain; a modified click follows the plain link. The menu, the landing, the contents sheet and every other link keep the curtain. `window.__chapterMorph` (`freeze`, `holdEnd`, `seek`, `release`) holds a morph for frame sheets.

## The About page (`/about`, rebuilt 15 Nov 2026)

The owner asked for the page to be made again from nothing on 15 Nov 2026 (request word for word in `docs/superpowers/specs/2026-11-15-about-page-request.md`, the design, the contracts between its parts and the calls in `...-about-page-redesign.md`). It says what The Aspirants is (the anime skin series of Mobile Legends: Bang Bang, its five phases, what was made around the skins, TheMLabel) and only points at the story. One 3D drone flies through the whole page. A second round on 16 Nov 2026 (`2026-11-16-about-phases-request.md`, and "Second round" in the design document) changed the first screen and gave every phase its videos, music, comic, drama and art. A third round the same evening (`2026-11-16-about-round3-request.md`, "Third round" in the design document) made the page end in TheMLabel. Code: `features/about/`. Rules:

- **The parts and where they meet.** `opening/` is the first screen and the film, `sections/` and `content.ts` the page below it (`sections/phase/` holds what a phase adds to its two skins), `tetra/` Tetra's corner of the second phase, `drone/` the WebGL layer and the director of the opening, `choreo/` the pure, tested arithmetic of the flight. They do not import each other. They meet in `layout.ts` (the film's numbers and the three layers: text 1, drone 2, film 3), `stage-bus.ts` (the phase of the opening, the title's reveal handle, a point for the drone to look at, the film's box) and `film-geometry.ts` (where the film's picture is for a scroll).
- **The drone is placed by anchors.** An empty `aria-hidden` element with `data-drone-anchor="<id>"` says where it rests: its centre and its width are the drone's. `hero`, `perch`, `center` and `dock` have their own logic in `choreo/path.ts`; every other anchor follows one rule (the drone is there while the anchor is in the middle band of the screen). To give the drone a new place, add an anchor in real empty space; never position it in the engine. Optional `data-drone-face` and `data-drone-turn`. From the dock on, a drone whose anchor has left the screen does not wait over the page's content: it draws back, small, into the page's margin on its own side (the lot, in `choreo/path.ts`), and a flight that the visitor's stop caught half way is finished to the nearer place after half a second (`settled`).
- **How it moves.** Where it should be is a pure function of the scroll and the measured anchors. The drone follows that point on a spring, its attitude comes from its own velocity (a scroll up is a flight up, nose first, never a rewind), tricks are timed one-shots that always finish, and at rest it eases upright, floats, blinks and looks at the pointer. It is never stateless in the scroll and never free of the path. It passes behind the film and in front of the text; the layer changes its place in the stack only where the drone is clear of the film. Keep the uncovered-fraction and on-screen tests in `choreo/` passing when a layout changes (`measured.fixture.ts` is a snapshot of the page's layout: take it again with `window.__aboutDrone.layout()`).
- **The model** is `public/models/about/drone.glb`, made by `scripts/about/drone/build.cjs` from the rigged FBX of the source folder (ten bones, unlit, no morph targets: the face is one atlas, the shader picks the cell, blinks and moves the eyes). The rig file's spring solver is not used. `public/img/about/drone.webp` is the still for a browser without WebGL (a failure handled, not a version). Never edit the outputs: change the script and run it (`scripts/about/README.md`). A file replaced under the same address needs the cache name bump in `lib/media-store.ts`.
- **The opening** is a clock, not the scroll, run by the director (`drone/director.ts`, not in the lazy chunk) once the loading screen has really gone: `wait`, `title` (the drone crosses the title from right to left and the title opens in bands behind it, in under two seconds), `landing`, `landed` (the description and the film's preview appear), `done`. The page root carries the phase as `data-about-intro` and a part hides itself for a phase only in CSS and only under `:root.js`. It goes straight to `done`, with everything shown, when `aspirants:intro` is `off` (tests), when the page opens part way down and when the visitor scrolls during the flight (the drone is never stopped: it flies on to where the scroll puts it). Without WebGL the bands still open and the still stands in the drone's place.
- **The film** is how the series started (the owner's choice, 16 Nov 2026): a loop cut from the studio's own film about the first Aspirant ideas, and a play control that opens the whole film from the collection. It is one `<video>` in a sticky stage. The preview and the big window have one shape (1920 by 810), so the morph is a translate, a uniform scale and a small tilt written on one element. No clip-path, no size is written. A stop inside the morph settles after one second (`useScrollSnap`, `idleMs: 1000`), the window then stands for `HOLD_SCREENS`. No scroll cue.
- **Transform and opacity only**, on the page and around the canvas. The top bar is bare for the whole page (`useNavLock`) and the browser's scrollbar is hidden (`BareScrollbar`), as on the long character pages. The canvas takes no pointer events: one round button follows the drone for hover, press and the keyboard, and nothing takes the focus on load.
- **Copy.** Only what the official account and the game's own texts say (the list is in the design document, "Facts the copy may use"). "Aspirant 1.0" is the owner's wording and "Phase" the official one: the page shows both. The drone's caption is the owner's ("The Aspirants official mascot"); nothing else is said of it. The description of the first screen is the owner's sentence and ends on TheMLabel's mark (`scripts/about/arts.py` makes the mark readable on the light page). Nothing from the site's novel is stated as a fact of the game. The page carries the fan-project notice at its foot. **It carries no shortcut to the takedown page**: the owner decided on 16 Nov 2026 that nothing on `/about` links to deletion or takedown, which overrides, for this page only, the rule that every 3D model and non-canon item has a `ReportLink` (the menu's legal links are the way there). Do not add one back.
- **The phases carry the collection's own files.** Each phase shows its official videos (a list to choose from beside a window), its music (a disc for each track, drawn in CSS 3D, with one shared audio store that follows the site's sound switch), Tetra (phase 2), the interactive drama (phase 4), its webtoon (phases 1 and 4) and its art. The lists and their order are the owner's and live in `features/about/phase-media.ts`, which runs while the page is built, names every video, track and comic by its id in the collection's data files and hands each phase only the records it needs (`sections/phase/types.ts`). Nothing is copied into `public/` for it and nothing is listed by hand in a component. A video of the collection is opened through `PhasePlayer` (it hands the captions of another origin to the player). Every part arrives in its own way, different from phase to phase, with transform and opacity only, and has the drone's place in the gap above it (`Part` in `sections/phases-view.tsx`).
- **Tetra** (`tetra/`, model made by `scripts/about/tetra/build.cjs`, README there) is drawn on a canvas of its own inside its section, loaded when the section nears the screen and never waited for by the loading screen. Code: `features/home/`. Rules:

- **One canvas, one renderer for the whole page** (`kernel/stage.ts`). There is never a second WebGL context on `/`. - **The kernel** (`kernel/`): `layout.ts` (the 16 sections and their lengths in screens), `scroll.ts` (the scene's own smoothed scroll `S`, in screens of the large viewport), `run.ts` (the section runner), `background.ts` (three stacked grounds, daybreak, storm and a plain colour; only the upper layer fades at a joint), `hold.ts` (a scroll hold, never `lenis.stop()`), `handoff.ts` (the way to `/about`), `lab.ts`. Every frame the kernel hides every actor, then the sections in range set the whole state of every actor they want drawn (last writer wins). After a jump (a scrollbar drag, Back, a probe `seek`) the sections that were passed run once at `local = 1`. A section's first frame must equal the last frame of the one before (the joints, `...-redesign.md` section 4.1). The lengths are pinned by `kernel/layout.test.ts` and by tests inside the sections: change them together.
- **Actors** (`actors/<name>/`: drone, duo, silverbolt, doll, selena, hand, gramophone, records, tetra; `fx/`: image-field, video-plane, logo, comic-marks, trail) are plain `.ts` classes with a thin `ensure<Name>` (built once through `actors/shared/ensure.ts`) and an `update(frame)` once a frame. The home never imports from `features/about/`. `window.__home.lab("<name>")` shows one actor on the real stage.

Waited is what the first screens need (about 5 MB: the drone and the pair, the hero cards, the carousel set, the first seconds of the strip); the rest is deferred in order of `priority`. Nothing is faked, nothing times out (see "Loading").

Sound comes only after a press: voice lines, the gramophone's track (it stops with a fade when the visitor leaves) and the trailer in the site's player.
