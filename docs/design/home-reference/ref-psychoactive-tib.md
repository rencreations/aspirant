## 1.7 Scroll phase 2: pull, hold, push (the floating previews) (c + m)

Same pin continues; `Q.pull`, `Q.hold`, `Q.push` are linear (ease none) tweens appended after t=T(2.3s): pull T x .78 (900 to 1602), hold T x .5 (1602 to 2052), push T x .78 (2052 to 2754).
Stage: `.bday--handover` is an invisible absolute container inside the pinned hero: width = scene row (1116), height `min(clamp(560px, 44vw, 800px), 100svh - 96px)` = 633.6, centered. It holds 12 cards (`.bday__card`): width `clamp(150px, 14vw, 270px)` (202 at 1436), `aspect-ratio 1.45/0.74`, radius 4px, bg #2a2a2a, `will-change: transform`, `img` object-fit cover. Card 0 (`--reel`) is a stand-in for the video itself, card 10 (`--lead`, second to last in mode 1) is the lead picture that later flies into the next section.
Every frame (ticker) each card gets `transform: translate(-50%,-50%) translate(xpx,ypx) scale(s)`, `z-index`, `opacity`, and (mode 1) `filter: blur(b px)`. Orbit pose for card e (n=12): i = (n - e) mod n ; a = i/(n-1) (0 = leader, 1 = tail) ; angle o = R - G[i] where G = cumulative angular gaps of a geometric series: gap ratio .88, total span .62 x 2PI = 3.896 rad (first gap = .62 x 2PI x (1-.88)/(1-.88^(n-1)) = 0.619 rad, shrinking x.88 each); s01 = (sin(o)+1)/2 ; x = cos(o) x rx, y = sin(o) x ry with rx = W/2 - cardW x .425 (472), ry = H/2 - cardH x .5 (265) ; scale c = 1.25 x (0.4/1.25)^a x (0.82 + 0.18 s01) ; z = round(100 s01) ; opacity = (1 - (1-.22) a^.85) x (0.65 + 0.35 s01) ; blur = a > .35 ? ((a - .35)/.65) x 1.6 : 0 px. So it is a comet-like train of 12 cards on an ellipse: leader 1.25x opaque, tail 0.4x, 22% opaque, up to 1.6px blur, arc about 223 degrees, front arc has higher z.
Rotation R: `R += dt x 0.09 / zoom` (about 5 degrees per second, ambient drift) PLUS scroll travel: `R += (dTravel x ge)/zoom` with `dTravel = pull x .78 + hold x .5 + push x .78` in timeline units, `ge = (4PI/12)/0.5` (the train advances 2 slots = 60 degrees per hold-length of scroll) and the initial R0 = PI/2 - (mean of the pull travel) so the arrangement at the end of the pull is a nice composition.
Camera dolly (the key trick): the whole stage is a scaled/translated copy so that card 0 coincides with the video's current rect. Let S = rect of the video wrapper (1116x628 at the end of phase 1) and T0 = natural rect of slot 0 (center + pose offset, width cardW x s). For pull progress c = easeInOutQuad(pull): target rect X = interpolate(S -> T0) with LOG interpolation of width: `w_i = S.w x (T0.w/S.w)^c`, position fraction `a = (w_i/S.w - 1)/(T0.w/S.w - 1)` (so zoom speed looks constant), height from an interpolated aspect ratio (16:9 -> 1.959). Zoom factor `Z = X.w / (cardW x s0)`; every card: `translate = (X.center - stageCenter) + (card.offset - slot0.offset) x Z`, `scale = card.s x Z`. Result: at pull 0 the stage is zoomed in about 5x (cards huge, off screen) and the video fills its window; at pull 1 cards read at normal size around the center. Measured card scale for the reel stand-in: y=1000 -> 5.16, 1200 -> 2.99, 1400 -> 1.36, 1600 -> 1.09, 2000 -> 1.24 (orbits, no more zoom), 2400 -> 2.82 (push zoom in again), 2600 -> 5.56.
The video-to-card swap ("roll"): the real `<video>` strip is clipped and moved with the same rect; when pull >= 0.6 `roll` tweens 0 -> 1 (0.85s `power4.inOut`, back 0.45s `power2.out` when pull < .6): the video's clip-path becomes `inset(n + roll x t x 100% 0 n 0 round r)` and translates up (`y -= roll x X.h`), i.e. it rolls shut upward while the card 0 image `translateY((1-roll) x 100%)` slides up into place. At roll >= 1 the video element is `visibility:hidden` (it is replaced by the card). This is the moment (y = 1321 at 900 vh) the video becomes just one of the floating cards.
Card opacity fades in with c: other cards `opacity x smoothstep(0,.2,c)`; card 0 `(o + (1-o)(1-c)) x E` with E = 1 - smoothstep(.25,.85,push).
Text (SplitText words+chars of lead/big/lede, a paused timeline W scrubbed by progress e): `e = (clamp((pull - .65)/.35) x .4 + clamp(clamp(hold)/.6) x .6) x (1 - clamp(push/.5))`. W = chars of title pop opacity 0->1 in 0.01s each at random times within 0.5 (`stagger {amount:.5, from:'random'}`), lede chars random within .4 starting at .2, button `autoAlpha` with RoughEase (template circ.easeOut, strength 5, points 20, taper out, randomize, clamp) dur .5 at .35, two mono corner labels opacity 0->.5 stagger .1 at .1 with a 0.7s scramble (chars `A-Z0-9@#$%=+<>/?`). So text is NOT time-based: letters appear at random as you scroll and un-appear in reverse (e from y=1356 -> 2052, then reverse during first half of the push 2052 -> 2403).
Hold-phase life: while held (roll >= 1 and push <= 0) one card at a time swaps its picture every 1.1s (first after 3.2s) starting from the brightest card then going backwards: a second `img` is appended, loaded and decoded first, then `yPercent 100 -> 0` for the new and `0 -> -100` for the old over 0.85s `power4.inOut` (cards clip overflow). # Risks, contradictions and ways out

1. The reference "expand to cover the page" is only 16:9 at scene width (1116x628 at 1440x900; 1386x780 at 1706x950), then the dolly pull. Owner words ("cover the page big") conflict: implement the reference exactly, but allow the expanded window to use `W = min(1600, vw - 2 x pad)`; if the owner meant truly full-bleed, it is a one-line change of the final scale target (use `scale = max(vw/W, vh/(W x .5625))` at the END of phase 1, then pull back). Ask the design doc to decide.
2. Psychoactive's strip clip-path (animated `inset`) is allowed by our rules? `clip-path` animation repaints; CLAUDE.md says transform/opacity only for animation. Use two nested overflow hidden masks translated in opposite directions instead (like the story morph) or animate `scaleY` on a mask div with the inverse scale on its child (both transform). The strip -> frame change (25.97% to 0 inset + scale .45 -> 1) is a pure reveal: use a mask div with `transform: scaleY(k)` and a counter-scaled video child.
3. Blur on cards (filter) is not allowed; ScrambleText and SplitText are fine (text, no filter).
4. WebGL budget: psychoactive uses 3 contexts at once (mist, preview, hologram). Our page already has the drone, Tetra, Silverbolt... Merge: one shared fullscreen background canvas (mist), one strip canvas, drop the CRT hologram (or draw it in the same strip canvas).
5. Card previews as video are expensive; reference uses still images in cards (and one real video). Use stills first, upgrade only the 3 front cards to muted looped clips; sources must be the owner's films (D:\ren\aspirant, /collection/video/films) cut to about 3 s low-res.
6. TIB's pad is a procedural ironing board; do NOT reuse its look or the "SINCE 2007"/lines palette literally (green). Use our palette; keep behavior and numbers.
7. The reference hero hides below 768 px and uses a plain mobile video: the owner's CLAUDE.md demands one version for all devices. Make the same sequence work at phone widths by reflowing the scene (portrait: frame scale .7 and clip 21.98%, dots at 12%/25.95%, circle opacity .2, scene aspect free: measured CSS in 1.2 portrait rules).
8. Smoothing lag (scrub .5 and the e7 lerp) is part of the feel; do not remove it, but keep the pure function so the probe/test can set progress directly.
9.
