Do not ship it. 11. EXPORT HAZARD (cost me a wrong first prototype, caught in review): in Blender 4.5 the .blend's actions are slot based and its 15 NLA strips load with `action = None`. Assigning an action in a script without setting `arm.animation_data.action_slot = action.slots[0]` evaluates ONE pose for every frame, so the glTF exporter writes 2 keys per channel and a "clip" of 1.4 KB or 8 KB (gltf-transform `inspect` showing the same size for a 2 s and a 16 s clip is the tell). The fix that works (`SCRATCH\bakeutil.py`, `export_sb2.py`, `export_selena2.py`): for each wanted action, set action AND slot, step `scn.frame_set(f)`, `arm.update_tag()`, `view_layer.update()`, read the EVALUATED pose bones (`arm.evaluated_get(depsgraph).pose.bones`), write fresh actions with `fcurves.new` + `keyframe_points.foreach_set('co', ...)` (they get a "Legacy Slot"), wrap each in an NLA strip with `strip.action_slot = action.slots[0]`, export with `export_animation_mode='NLA_TRACKS'` (`ACTIONS` mode exported nothing). Then verify: every rotation channel must have about the frame count of keys (checked: 66/50/152/384 keys per channel). `D_she_root` must be re-based when its parent `root` is dropped: `basis = bone.matrix_local.inverted() @ evaluated_pose_matrix`. Every render and pose number in this digest was made after the slot fix (earlier ones were discarded and redone: `cmp_valid.png`).
